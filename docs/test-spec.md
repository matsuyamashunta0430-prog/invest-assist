## 1. テスト戦略

### 1.1 レイヤー構成

| レイヤー       | ツール                   | 目的                                                             | 実行タイミング                          |
| -------------- | ------------------------ | ---------------------------------------------------------------- | --------------------------------------- |
| ユニット       | Vitest                   | 純関数（ドメインロジック・スキーマ・フォーマッタ）の振る舞い検証 | pre-commit / CI / 開発中 watch          |
| コンポーネント | Vitest + Testing Library | React コンポーネントの DOM 出力とイベント反映                    | CI（Phase 1.5 で追加予定）              |
| E2E            | Playwright               | ブラウザを起動して画面遷移・URL シェア・リロード復元を再現       | CI（毎 PR）／本番デプロイ後（スモーク） |
| Lighthouse     | Lighthouse CI            | パフォーマンス・A11y・SEO スコア計測                             | デプロイ後（Phase 1.3 で追加予定）      |

### 1.2 テスト駆動方針

- **ドメインロジック**（`src/lib/`）はテストファースト。境界値（0、最大、不正入力）を必ず網羅
- **コンポーネント**は「振る舞い駆動」: ユーザー目線で「クリックしたら結果が変わる」をテストし、内部実装には触れない
- **E2E** は最重要パスのみ（深い分岐は単体に委ねる）

### 1.3 カバレッジ目標

| 対象                | 目標カバレッジ       | 現状                               |
| ------------------- | -------------------- | ---------------------------------- |
| `src/lib/**`        | 行 95% / 分岐 90%    | 計測未実施（テスト 35 件は網羅的） |
| `src/components/**` | 行 70% / 分岐 60%    | 未着手                             |
| `src/app/**`        | 行 50%（E2E で補完） | 未着手                             |

`vitest run --coverage` で V8 カバレッジを HTML 出力（`coverage/index.html`）。

## 5. 数値モデル回帰テスト（重点）

シミュレーターの「数値が業界標準と一致する」ことは MVP の最重要要件。Codex 役レビュー C1 でこの観点を明示。

回帰テストは以下のシナリオで `toBeCloseTo` で固定:

| 入力                                            | 期待 FV       | 許容誤差      |
| ----------------------------------------------- | ------------- | ------------- |
| monthly=30000, rate=5%, years=20, initial=0     | 12,330,000 円 | ±5 万円       |
| monthly=10000, rate=0%, years=1, initial=0      | 120,000 円    | 0（整数一致） |
| monthly=0, rate=12%, years=1, initial=1,000,000 | 1,126,825 円  | ±100 円       |

将来モデル変更（例: 月初払い annuity due に切り替え）はこれらのテストを失敗させてから、意図と合意の上で更新する。

## 6. CI でのテスト実行

`.github/workflows/ci.yml`（main への push / PR で発火）:

1. `pnpm install --frozen-lockfile`
2. `pnpm lint`（ESLint + Prettier）
3. `pnpm tsc`（型チェック）
4. `pnpm test`（Vitest 37 件）
5. `pnpm build`（Next.js プロダクションビルド）

すべて通った PR のみ main にマージ可能（Branch Protection は手動設定が必要）。

`pnpm test:e2e`（Playwright）は CI には組み込み未実施。Phase 1.5 で `webServer` 設定を CI 用に切り替えて追加予定。
